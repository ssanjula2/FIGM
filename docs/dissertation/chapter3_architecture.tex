\section{The 4-Layer Hierarchy}
The Framework-Independent Guideline Model (FIGM) establishes a 4-layer hierarchical abstraction architecture:
\begin{equation}
\text{Quality Domain (Layer 1)} \longrightarrow \text{Architectural Concern (Layer 2)} \longrightarrow \text{Abstract Language Primitive (Layer 3)} \longrightarrow \text{Guideline Rule (Layer 4)}
\end{equation}

\section{Abstract Language Primitives (ALPs)}

\section{AST Normalization Protocol}
FIGM's parsing layer is a framework-and-rule-gated hybrid, not a uniform AST engine. For 23 of the 25 canonical rules, source is parsed into a genuine TypeScript-compiler AST (\texttt{ts.createSourceFile}) and converted into unified, normalized \texttt{ASTNode} objects for static evaluation, wherever the input syntax is genuinely TypeScript/JSX-parseable — React, Next.js, plain JS/TS, and the TypeScript class body of Angular components. The remaining 2 rules (Angular's \texttt{*ngFor} \texttt{trackBy} rule and its template method-call-invocation rule, both operating on Angular \emph{template markup} rather than the TypeScript class body) are evaluated by a text-heuristic regex path instead, since the TypeScript compiler cannot parse Angular template syntax. The same text-heuristic path is used for \emph{every} rule when the input is a Vue SFC template, since Vue SFC templates receive no real-AST treatment for any of the 25 rules today. Every diagnostic FIGM emits is labeled with a \texttt{sourceKind} field (\texttt{REAL\_AST} or \texttt{LEGACY\_TEXT\_HEURISTIC}) recording which of the two mechanisms actually produced it, so this distinction is inspectable in the tool's own output and is never hidden from the reader.
